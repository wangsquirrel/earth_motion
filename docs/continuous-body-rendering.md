# 每帧天体运动与隐藏图层修复

日期：2026-10-01。对照版本：`2ae0966ed728c3fc8ed28da7714103b59a336c64`。

## 问题与原因

用户在 1 秒推进 1 周、仅显示太阳时看到跳动。仿真时钟本来已经逐帧计算；100ms 的 UI 日期刷新不是太阳位置的更新来源。

原 Space 天体层按速度/参考系使用 16ms 或 33ms 墙钟门槛，并通过 React state 交付位置。60Hz 渲染下 33ms 门槛只能每两帧更新，75Hz 下会每三帧更新。日出日落还会卸载/重建太阳和文字。Earth 层另有 16ms 门槛，月相采用 60 秒仿真时间阈值。太阳日轨形状则使用 1 小时仿真时间与 100ms 墙钟双重门槛。

另外，关闭恒星后仍无条件绘制 3200 颗装饰背景星；天球参考系的地平叠加层也会在高倍速自动淡化到正常强调的 0.35。这些都不符合“开关应减少无关负担、所有倍速保持同一展示规则”的要求。

## 实现

- 太阳、月亮、行星按每个实际 render frame 的精确 `simDateRef` 更新 Three 对象的位置与显隐。没有按倍速分支、位置墙钟节流、低分辨率替代、缓动滞后或减速。
- 太阳、月球、行星在图层开启期间保持对象与文字挂载；越过地平只改 `visible`，保留原有地平判断。太阳光线与太阳在同一帧同步。
- 月相仍使用原 shader，直接更新 uniform。运动与月相不再触发 React state 提交。
- 日轨保留 145 个原始样本、原 `splitPointSegments` 分段、7 个时间标记、虚线相位、线宽、颜色与透明度。常驻 Line2 池和 Float32 缓冲每帧更新，避免 React 重建几何；相同精确时间和地点可复用。
- 月亮/行星关闭后停止对应求解与绘制，恒星开关同时控制星表与原有 3200 颗装饰星。日轨、银河和周年路径的原有开关继续生效。恢复时取当前时间地点，不显示缓存中的旧时刻。
- 地平叠加在所有倍速保持正常完整强调。没有新增自动减质、拖尾或替代观测模式。
- 小屏文化按钮由七列改为五列，较大屏仍七列，避免 400px CSS 视口下三字星官名折行。

## 高倍速的采样边界

项目区分“太空视图”与其中的“地平/天球参考系”。两种参考系原有语义均保留。

用现有天文计算函数在北纬40°、经度0°、2026-03-20 数值采样：

- 地平参考系，1周/秒：60Hz 两帧之间经过约2.8小时，太阳相邻角位移约42.008°；旧33ms门槛在60Hz下每两帧更新，约84.017°
- 同一倍率在天球参考系：太阳沿周年轨迹每帧约0.116°，日运动由地平叠加的旋转表达
- 地平参考系每秒约七个昼夜，春分附近有约14次地平显隐转换。这是真实时间倍率下的运动，不能用关闭其他天体消除

逐帧更新去除了程序额外丢弃的位置更新；它不能让有限刷新率在一帧内显示无限多个时刻。因此不能把此修复、CPU 基准或数值回归描述为“保证任意设备在1周/秒绝对平滑”。也没有用冻结时刻或自动改变参考系来掩盖这一限制。

## 验证方法与边界

在本机 AMD EPYC 9V74、Node v24.19.0 上，以 `--speed=604800`、每轮120个有效帧、七轮中位数进行 CPU 对照：

| 场景 | 仅太阳：旧版→新版 CPU ms | 日月与7行星：旧版→新版 CPU ms |
| --- | ---: | ---: |
| Space 地平参考系 | 9.444 → 1.582 | 75.448 → 18.047 |
| Space 天球参考系 | 10.101 → 1.096 | 64.291 → 18.800 |
| Earth | 2.810 → 1.490 | 76.457 → 21.148 |

这里每120帧是累计 CPU 时间，不是每帧耗时或实际 FPS。旧版计时人为给足40ms墙钟间隔，让其33ms门槛每次都通过；新旧均断言120次精确太阳位置更新，因此没有通过少算旧版帧数获得速度比。全部背景图层/轨迹关闭，文字因无浏览器环境被省略；结果不含GPU、文字glyph、UI时钟调度或整场景开销。V8计数确认仅太阳的月球/行星/月相求解在挂载及播放均为0；全开120帧对应120/840/120次，太阳均120次，新版动画React提交为0。

3600×完整过程另保留在 `live-body-performance-3600.json`，最初过程的摘要在 `live-body-performance-initial-summary.json`。不同过程有波动：最初 Earth 仅太阳测得2.095→2.296ms，不能据后一次较快就断言所有设备与所有场景必然加速。主要确定改进是移除额外显示节流、取消动画React提交、隐藏图层停止对应工作。

复现：`node scripts/benchmark-live-bodies.mjs --baseline=2ae0966 --speed=604800 --frames=120 --rounds=7 --output=docs/live-body-performance.json`。另有24组配置共1440个60Hz虚拟帧的精确位置检查，覆盖所有四档倍率、两种Space参考系与Earth、仅太阳与全开。

- `tests/liveSpaceBodies.test.ts` 使用真实 React/R3F 与 Three 对象，覆盖两参考系、四档速度及反向数值压力测试、600个精确帧位置、光线同步、地平反复显隐、对象/材质稳定、暂停、位置输入和隐藏恢复首帧。UI目前仍只提供原有正向倍速
- `tests/earthBodyFrames.test.ts` 检查逐帧位置/月相、暂停输入、隐藏求解次数、恢复首帧与无 React 运动提交
- `tests/spaceDiurnalLayer.test.ts` 对照原 Drei LineGeometry/Line2 的 Float32 位置、逐段 dash 距离、材质、bounds、所有倍速、极点/季节、精确时间变动、显隐恢复和 viewport resize
- `scripts/benchmark-live-bodies.mjs` 与 `docs/live-body-performance.json` 记录相同有效帧工作量的 CPU/求解次数对照；不是 GPU、真实浏览器帧率或完整场景性能测量
- 原文化、天文、时钟、缓存、投影等回归继续运行，完整检查包括 `npm test`、`npm run check`、`npm run lint`、`npm run build`
- 独立审核额外将真实 `useSimulationTime` 与天体/路径组合挂载，确认暂停输入和图层恢复的首个渲染帧；并实际挂载旧 Drei 路径与新对象逐属性比较。未发现确认缺陷。最终完整34项测试、类型检查、lint、构建均通过

云浏览器明确禁用 WebGL，旧版白屏；当前错误边界保留可操作的控制/文化面板。线上文化、语言、图层、参考系、日期/地点与 1180×757、500×757、400×606 CSS 响应式控制已检查；后者来自桌面窗口和缩放，不是真实手机。实际3D画面、GPU时间、FPS、触摸拖拽和像素等价性尚未验收。代码和 Float32 数据对照只能证明其各自覆盖的行为，不能替代真实图形设备验证。
